Description

From the course catalog:

This course is a continuation of CSC 110. Topics include advanced data structures (linked lists, stacks, queues, trees, hash tables), recursion, abstract data types, introductory algorithms, and intermediate object-oriented programming.

Objectives

CSC111 and CSC111L share objectives. Upon successful completion of both courses, students should be able to:

  1. Design, write, document, and test sophisticated programs using an object-oriented language.
  2. Identify situations where recursion is an appropriate problem solving strategy.
  3. Compare array and linked data structures and implement problem solutions using each.
  4. Describe the characteristics of stack and queue data structures and implement problem solutions using each.
  5. Describe characteristics of tree data structures and implement problem solutions using them.
  6. Explain search and sorting methods and implement programs using each.
  7. Describe factors that determine algorithm efficiency and measure the efficiency of searching and sorting algorithms.

Grading

The grading system for my classes aims to be simple and transparent, and I try to incorporate some ideas from labor-based grading. It works as follows:

  • Larger assignments are broken into tasks:
    • Each task has a point value and is marked complete (you get 100% of the task’s points) or incomplete (you get 0 points for the task) when your work is graded. There is no partial credit for incomplete tasks.
    • Each task will list one or more requirements that must be met for the task to be considered complete. If you meet the requirements, then the task is complete. If not, then the task is incomplete.
    • If revisions or multiple attempts are allowed, then each attempt will receive a separate score. Only the highest-scoring attempt for an assignment counts towards your grade.
  • There may be smaller assignments that award points if they are completed, or assignments that reward points for some ongoing obligation (such as weekly practice exercises or class participation).
  • Your final grade is the sum (not the average) of your assignment grades and uses the letter grade scale in QU’s grading system. This means five points on any assignment is equal to five points on your final grade.

My goal is to emphasize the work you put in and how much you engage in activities that will help you learn the material rather than the results of this work.

Artificial Intelligence (AI) Policy

As stated in the AIA policy, all AI use is banned in this class. This policy includes some additional information and expands on the school’s AI policy (https://catalog.qu.edu/university-policies/artificial-intelligence-policy/), which you should read first. We’re primarily talking about “generative AI” as defined in the school’s policy.

Disclosures

If an exception is made that permits AI use, then all AI use must be clearly documented and any AI-generated material must be clearly marked as such. Any undisclosed AI use, regardless of whether you had written permission to use AI, is a violation of our AIA policy.

Email and Communication

When communicating with me or your classmates, you should not use AI tools to generate or edit your writing. If someone is communicating with you, then they probably want to talk to you and not a chatbot.

If you’re worried that you will come across as unprofessional or don’t think you’re good at written communication, that’s not a reason to rely on AI. People can generally tell when they’re reading text generated or edited by an LLM, and that gives a much worse impression than some spelling mistakes or poorly-worded sentences. You will also not get any better (in fact, you’ll probably get worse) at writing or communicating if you outsource that to a chatbot.

AI Software

You are not allowed to use software or plugins/add-ons with AI features for this class unless those features are disabled. You are responsible for disabling them and ensuring they remain disabled throughout the semester.

If you use the software that I recommend elsewhere in the syllabus, install and configure it as directed, and don’t add any additional plugins, then you don’t have to worry about accidentally enabling some AI feature and getting in trouble for violating this policy. In the unlikely event that I recommend something with an AI feature and don’t realize it, then that’s my fault, not yours.

However, if you don’t use the recommended software or if you use plugins not covered in the directions, then you are responsible for ensuring that your software does not have any features that violate our no AI policy. Ignorance of AI features in this software is not an excuse; it’s your job to vet the software and determine whether it is allowed by our policy. If you don’t want that responsibility or want me to vet software for you, then use the recommended software.

Rationale

There are a few reasons that I do not allow AI use and advise against using it yourself:

  • There are a multitude of ethical problems with how AI models are trained, how AI companies operate, the environmental impact of data centers, and how these tools are used by many companies. This is not something I want to contribute to or help normalize.
  • This is a class, and our primary goal is for you to learn new skills and improve existing skills. Practice is a necessary part of this, and you can’t outsource practice to an LLM. The LLM may be able to do the work for you, but you won’t get any better or learn anything from letting a chatbot do your work. This is no different from outsourcing the work to another person.
  • AI tools are new and changing rapidly. They are also not difficult to pick up. Even if you believe you will need them in your career, investing time into learning tools that may be obsolete before you graduate will not be as useful as learning skills related to your field. The skills that make you a good programmer without AI tools will also make you a good programmer with AI tools, and you’ll be able to use them much more effectively than someone who only knows how to vibe code.

My AI Use

I do not currently use AI tools for anything. This includes coding, emails, creating material for this class, grading, etc. I tried some of these tools when they became available, but I did not find them useful and am not comfortable with using them for ethical reasons as I mentioned earlier.

Student Proposals

As an experiment, I want to encourage my students to have more of a say in how this class is run. Think of this as an attempt at introducing some classroom democracy to offset the dictatorial power I have as your instructor. This is completely optional, and I’m happy to run the class as I normally would if there’s no interest in engaging with this.

Proposals and Voting

I consider much of this class (policies, assignments, etc.) to be negotiable. There are limits to what I’m willing to change (see the section on instructor veto), but I will try to work with the class on any proposals that are voted through.

In order for this to work, the class needs to discuss and vote on proposed changes, and there needs to be a threshhold for passing a proposal. I’ll establish a default process here, but the class is free to propose and vote on a new process if they would like to change it.

Discussion and Negotiation

Anyone can request time during class to discuss a new proposal. I will step back and give the class up to 10-15 minutes for these discussions, and I can join the discussion at any point if someone wants my feedback or to negotiate what would make the proposal acceptable on my end. I will otherwise try to keep my involvement to a minimum and let this be a student-directed conversation.

I should also be able to set up a discussion board on Canvas, which you can also use to discuss any new proposals.

Voting

Students can vote during class or on the Canvas discussion board. For a proposal to pass, it will need a number of “yes” votes equal to the class size minus two. This is based on the number of students enrolled in the class, not the number of students present. For smaller class sizes, I might change this to class size minus one or unanimous support, but at our current size I believe this is a reasonable default. Again, the class is free to change this to something else, such as a simple majority.

Instructor Veto

As the instructor, I still reserve final say in whether to implement a proposal. I will generally only veto or modify a proposal for the following reasons:

  • If a proposal interferes with any of my obligations to the university or violates university policy, then I cannot implement it. For example, I can’t turn this into a class about origami or assign grades based on random dice rolls. I’m also not likely to change the AI and AIA policies.
  • If a proposal would be unfair to some students, then I will not implement it. This would generally fall into the previous category (violates school policy), but I still think it’s worth mentioning.
  • If a proposal would require an unreasonable amount of work on my end or make my job significantly more difficult, then I may refuse to implement it. For example, if the class wants me to design a highly-structured project to replace an existing assignment, then I probably won’t have time to do this and would refuse. However, if the class wants to propose a specific alternative to an existing assignment, then that’s something I can work with.

Commands

You interact with a terminal by typing a command and reading the command’s output. This section will cover the structure of a command and some terms you’ll need to know to understand these commands.

There are differences between Windows and Unix-like systems, but most of these differences won’t matter if you are using a bash emulator on Windows. For example, Windows uses a backslash to separate directory names in paths, but your bash emulator should allow you to use a forward slash as if you were on a Mac or Linux computer. My notes focus on Unix-like systems, but I will try to note differences between Git Bash and bash/zsh when they come up.

Terms

Some terms that will be used to explain terminal commands. Refer back to this list if you come across something you don’t understand.

  • Directory: another word for a folder on your hard drive. A directory can contain files and other directories.
    • Your working directory is the directory in which your terminal (or another program) is currently running. Your terminal has direct access to files in its working directory.
    • Your home directory is the where the terminal starts. This should be your user folder: /home/username on Linux, /Users/username on Mac, and C:\Users\username (displayed as /c/Users/username in a bash emulator) on Windows.
  • Path: a path is the location of a file or directory. It consists of directory names separated by forward slashes (/). The path ends with the name of the file or directory it leads to.
    • An absolute path tells you how to reach a file or directory from the root of a file system. An absolute path starts with a forward slash on Unix-like systems. For example, the absolute path to my Desktop can be written as /home/zach/Desktop or /home/zach/Desktop/. The forward slash at the end of the path is optional, and it can only be included when the path points to a directory (such as the Desktop folder).
    • A relative path tells you how to get from one location (usually your working directory) to a specific file or directory. For example, if I were in the directory /home/zach and wanted to reach /home/zach/Desktop/notes.txt, then the relative path Desktop/notes.txt tells me how to reach that file from my current location.
    • Your computer also has a list of paths that it checks whenever you ask it to run a program. This list is stored under the label “path” or “PATH”, and we can just refer to it as “the path”. When you install a new program, the installer will usually add its location to the path or create a shortcut in a directory that was already on the path. If a program is on the path, then you only have to type its name to run it. If a program is not on the path, then you have to type a path to that program to run it.

Command Structure

Commands on the terminal can refer to programs or built-in functions. Sometimes you’ll only need to type the name of a command, and sometimes you’ll need to include arguments after the name. An argument is an additional piece of information that changes the command’s behavior.

Here are three examples using the ls command:

  • ls: lists contents of working directory; no arguments
  • ls Desktop: lists contents of the Desktop directory; Desktop is an argument
  • ls -a Desktop: lists contents of the Desktop directory, including hidden files; -a and Desktop are arguments

The third command includes a special type of argument called a flag. A flag normally starts with one or two dashes, and it enables a setting in the command. The -a flag tells ls to include hidden files in its output.

Spaces

Spaces separate each part of a command (the name and arguments). This can cause problems if you use spaces in your filenames. For example, if you have a folder named My Folder, then the command ls My Folder will not list the contents of My Folder. It will instead try to list the contents of two directories: My and Folder. We can fix this by quoting the path (ls 'My Folder') or escaping the spaces (ls My\ Folder), but this is easy to forget and takes longer to type. If you avoid using spaces in filenames, then you don’t have to worry about this.

Command History and Tab Completion

Your terminal saves a history of every command you enter. You can go back through this history with the up and down arrow keys, which lets you repeat a command without retyping it.

The tab key will attempt to complete the path or command name you are currently typing. This saves a lot of typing AND helps you avoid mistakes. If you haven’t typed enough to narrow it down to one possibility, then you can hit tab again to see a list of every remaining option.

Examples

If I want to show you what it looks like when you run a terminal command, then I will include both the command and its output. It might look something like this:

$ ls -a ~/Desktop
. .. todo.txt lesson_plan.md

Terminals display a prompt when you are allowed to type a command. This prompt can include your username and working directory, and it usually ends in a dollar sign, percent sign, or other special character. When you type a command, it will appear after that special character. For example, the prompt on my work desktop terminal looks like this before I type a command:

zach@zach-work-desktop:~$

If I type the command ls -a ~/Desktop, then it will appear after the prompt:

zach@zach-work-desktop:~$ ls -a ~/Desktop

We usually use a lone dollar sign at the start of a line to abbreviate this prompt, but it is not part of the command. For example, if you wanted to imitate the example below, then you would only type ls -a ~/Desktop on your terminal and press the enter key.

$ ls -a ~/Desktop
. .. todo.txt lesson_plan.md

$ cd Desktop

$ ls
csc110

Navigation

Before you can use the terminal to run your programs, you need to know how to navigate your filesystem and find those programs. This is essential for doing anything in the terminal. The following three commands will help:

  • pwd (print working directory): tells you where you are
  • cd (change directory): moves the terminal to a new folder
  • ls (list): lists files and folders in your current location

pwd

Run pwd to print the absolute path of your working directory. You won’t need to use this command often, but it’s useful if you aren’t sure exactly where you are.

cd

Running cd with no arguments will take you to your home directory. Running cd followed by a directory’s path will take you to that directory. You can use a relative or absolute path.

For example:

  • If I’m in the directory /home/zach/, which contains the directory Documents, then I can move into Documents with cd Documents or cd /home/zach/Documents/.
  • If I’m in /home/, then I can move into Documents with cd zach/Documents or cd /home/zach/Documents/, but not cd Documents.

Finally, there are a few special names that act as shortcuts for commonly-used directories:

  • ~ Refers to your home directory. In the above example, I could reach my Documents folder from any location with cd ~/Documents.
  • . Refers to the working directory. You won’t need to use this one right now, but you may see it in some paths or after running the ls -a command.
  • .. Refers to the working directory’s parent directory. This is useful if you want to go back to a directory that appears earlier in your path. For example, if your working directory is /home/zach/Documents/csc110/homework/, then .. refers to /home/zach/Documents/csc110/. You can use .. multiple times to go back further. In the previous example, ../.. would refer to /home/zach/Documents/, and cd ../.. would move me to that directory.

ls

Running ls with no arguments will list the contents of your working directory. Running ls followed by a path will list the contents of that directory (if the path points to a directory) or the name of that file (if the path points to a file).

This command is helpful if you’re looking for a file or want to see what’s in your current location.

The -a flag mentioned earlier will show hidden files, and the -l flag will show more details about the files.

Maze File Format

A properly-formatted maze file is structured as follows:

  • first line: the rows and cols separated by a space
  • maze: one line for each row, with each line containing a number of characters equal to the cols (in other words, the exact output of the toString method)
  • comments/extra: may have additional lines of text after the maze; these should be ignored when reading the file

# # #   #   #   # #

# # #   #   #   # #
# # ### ### ### ###

This is extra text in the comments section. Your code shouldn't read this part,
or at least shouldn't use it when initializing a Maze object.

Coordinates

Our maze uses row/column coordinates instead of x/y coordinates. We could design the maze class to use either, but once we’ve made that choice we need to be consistent with the order of these coordinates and how we refer to them.

If we use x/y coordinates, then we expect the following:

  • x is the horizontal axis and y is the vertical axis
  • x is the first coordinate, and y is the second coordinate
  • width is the first dimension, and height is the second dimension
  • up is usually positive and down is usually negative

If we use row/column coordinates, then we expect the following:

  • row is the vertical axis (changing rows moves you up or down), and col is the horizontal axis
  • row is the first coordinate, and col is the second coordinate
  • rows is the first dimension, and cols is the second dimension
  • up is usually negative and down is usually positive

If you want the short version: row/col puts the vertical axis first, and x/y puts the horizontal axis first. To avoid mixing up the order and introducing some very annoying bugs, do not refer to your coordinates/dimensions as x, y, width, or height anywhere in your code! Use “rows” and “cols” instead of “width” and “height” to refer to the dimensions of a maze for the same reason.

If this sounds confusing, don’t worry! The difficulty here isn’t the code you’ll be writing, it’s thinking about the difference between x/y and row/col coordinates. I’m only explaining it so you know why the assignment works this way and can avoid some of the more common mistakes. You shouldn’t need to worry about the above explanation while coding as long as you follow the advice about not referring to variables as x, y, width, or height.

Task 3: Recursive Solve Method (5 points)

Add the MazeConstants.java file to your project folder before writing the solve method:

public class MazeConstants {
    public static final char EMPTY = ' ';
    public static final char PATH = '.';
    public static final char START = 'S';
    public static final char END = 'E';
    public static final char VISITED = 'v';
    public static final char WALL = '#';
}

We must obey the following rules when trying to solve the maze:

  • positions containing the space character ' ' are considered empty
  • positions containing any other character are considered occupied, and we cannot move through them
  • when we begin solving the maze, we will start at an empty position within the bounds of the maze
  • from our current position, we are allowed to move to the adjacent north, south, east, or west position as long as it is empty
    • for example, we could move from r3c7 to r4c7, which is one cell south, but not to r5c7 (two cells south) r4c8 (one cell diagonally southeast)
  • our goal is to find a path that leads from the start position to the end position

You will use the following recursive algorithm to solve the maze:

  • input
    • a maze to solve
    • a start row and start column
    • an end row and end column
  • first base case
    • condition: our start position is out of bounds or isn’t empty
      • you can use the maze’s get method to check whether a position is empty: m.get(12, 27) == MazeConstants.EMPTY will tell you whether r12c27 is empty
    • result: we’ve failed to solve the maze because we can’t move out of bounds or through an occupied cell
  • second base case
    • condition: our start position matches our end position
    • result: we’ve solved the maze!
  • recursive case
    • condition: base case conditions are false (in code, this should just be an else)
    • mark our starting position as MazeConstants.VISITED
      • you can use the maze’s set method to mark a position: m.set(5, 11, MazeConstants.VISITED); would mark r5c11 as visited
    • for each position we are allowed to move to, attempt to solve the maze starting at that position
      • these positions are (row - 1, col), (row + 1, col), (row, col - 1), and (row, col + 1)
    • if we succeed in solving the maze, then mark our starting position as MazeConstants.PATH

You must implement this algorithm as a recursive static method:

  • name: solveMaze
  • return type: boolean (true if solved and false if not)
  • parameters:
    • m: Maze is the maze to solve
    • startRow: int is the start row
    • startCol: int is the start column
    • endRow: int is the end row
    • endCol: int is the end column

public class Example3 {
    public static void main(String[] args) {
        // if there are no program args, then the program ends!
        if (args.length == 0) {
            System.out.println("Sorry, I need program args.");
            // ends the program early
            // exiting with a nonzero value indicates to other programs that
            // something went wrong
            System.exit(1);
        }

        // check whether there are an even or odd number of args
        if (args.length % 2 == 0) {
            System.out.println("Even arg count detected!");
            // call another static method
            even(args);
        } else {
            System.out.println("Odd arg count detected!");
            // call another static method
            odd(args);
        }
    }

    public static void even(String[] args) {
        // print only the even-numbered args
        for (int i = 1; i < args.length; i += 2) {
            // our target audience is non-programmers, and their brains aren't
            // zero-indexed
            System.out.printf("%d. %s\n", i + 1, args[i]);
        }
    }

    public static void odd(String[] args) {
        // print only the characters encoded as odd numbers
        // why are we doing that? hey, look! an enhanced for loop!
        for (String arg : args) {
            // wow, a nested loop!
            for (int i = 0; i < arg.length(); i++) {
                // get character
                char c = arg.charAt(i);
                // checking if odd
                if (c % 2 != 0) {
                    System.out.print(c);
                }
            }
            // line break after each arg
            System.out.println();
        }
    }
}

    static void main(String[] args) {
        // a circle is defined by three values
        double x = 11;
        double y = 8;
        double radius = 6;

        // note: we can call these methods with any arbitrary values
        printCircle(10, -4, 15);

        // use methods with our variables
        printCircle(x, y, radius);
        drawCircle(x, y, radius);
    }

    static void printCircle(double x, double y, double radius) {
        double area = Math.PI * radius * radius;
        double circumference = 2 * Math.PI * radius;

        System.out.printf(
                // a multiline string literal isn't necessary, but it's easier to read our
                // format string like this
                """
                CIRCLE
                    CENTER: (%.2f, %.2f)
                    RADIUS: %.2f
                    AREA: %.2f
                    CIRCUMFERENCE: %.2f
                """,
                x, y, radius, area, circumference);
    }

    static boolean containsPoint(double cx, double cy, double cr, double px, double py) {
        double dx = cx - px;
        double dy = cy - py;
        // squaring the radius is faster than taking the square root of (dx^2 + dy^2)
        return dx * dx + dy * dy <= cr * cr;
    }

    // we can use containsPoint to make some simple ascii art
    static void drawCircle(double cx, double cy, double cr) {
        for (int y = 0; y < 30; y++) {
            for (int x = 0; x < 80; x++) {
                if (containsPoint(cx, cy, cr, x, y)) {
                    System.out.print('O');
                } else {
                    System.out.print('.');
                }
            }
            System.out.println();
        }
    }
}

public class Circle {
    private double x, y;
    private double radius;

    public Circle() {
        this.setX(0);
        this.setY(0);
        this.setRadius(0);
    }

    public Circle(double initX, double initY, double initRadius) {
        this.setX(initX);
        this.setY(initY);
        this.setRadius(initRadius);
    }

    public void setX(double newX) {
        this.x = newX;
    }

    public void setY(double newY) {
        this.y = newY;
    }

    public void setRadius(double newRadius) {
        if (newRadius < 0) {
            this.radius = 0;
        } else {
            this.radius = newRadius;
        }
    }

    public double getX() {
        return this.x;
    }

    public double getY() {
        return this.y;
    }

    public double getRadius() {
        return this.radius;
    }

    public double getArea() {
        return Math.PI * this.radius * this.radius;
    }

    public double getCircumference() {
        return 2 * Math.PI * this.radius;
    }

    public String toString() {
        return String.format("Circle(center: (%.02f, %.02f), radius: %.02f)", x, y, radius);
    }
}

from Java 25 spec, section 11.2:

Error classes are exempted because they can occur at many points in the program and recovery from them is difficult or impossible. A program declaring such exceptions would be cluttered, pointlessly. Sophisticated programs may yet wish to catch and attempt to recover from some of these conditions.

Run-time exception classes are exempted because, in the judgment of the designers of the Java programming language, having to declare such exceptions would not aid significantly in establishing the correctness of programs. Many of the operations and constructs of the Java programming language can result in exceptions at run time. The information available to a Java compiler, and the level of analysis a compiler performs, are usually not sufficient to establish that such run-time exceptions cannot occur, even though this may be obvious to the programmer. Requiring such exception classes to be declared would simply be an irritation to programmers.

For example, certain code might implement a circular data structure that, by construction, can never involve null references; the programmer can then be certain that a NullPointerException cannot occur, but it would be difficult for a Java compiler to prove it. The theorem-proving technology that is needed to establish such global properties of data structures is beyond the scope of this specification.

ADTs

  • Abstract Data Type (ADT):
    • abstract: no implementation
    • defines a data type “in terms of a type and a set of operations on that type” (section 1.2.1)
    • i.e. what methods do we want this data type to have?
    • specific data structures are implementations of an ADT
    • can have multiple implementations with different strengths and weaknesses
    • in Java, an interface represents an ADT
  • example (from Java’s standard library):
    • ADT: java.util.List
    • data structures: java.util.ArrayList, java.util.LinkedList

Unordered List ADT

  • simple ADT for our first data structure implementations
    • unordered: makes no guarantees about the position of elements within the list
    • less useful than a typical list, but simpler to implement
    • has some optional features we can add later as we learn more about data structures
    • lets us explore some early algorithms next week as part of different implementations
    • stores integers for simplicity
  • UnorderedIntList:
    • init(capacity: int) our constructor, not an actual method and not part of the interface, initializes an empty list with the given capacity
    • capacity(): int returns the amount of space in the list
    • size(): int returns the number of elements stored in the list
    • add(element: int): boolean adds element to the list and returns whether it succeeded (adding can fail if the list is full)
    • remove(element: int): boolean removes one occurrence of element from the list (element could appear multiple times) and returns whether or not it removed anything
    • contains(element: int): boolean returns whether the list contains element
    • clear() removes all elements from the list
    • toArray(): int[] returns an array with a length equal to the list’s size() containing every element in the list
  • first implementation: UnsortedIntArrayList
    • stores elements in an array
    • does not resize if it runs out of space (we’ll look at how to do this later)
    • removes an element by overwriting it with the last element of the list
    • adds new elements at the end of the list
    • important concepts: garbage data and the distinction between the list and its internal array

Recursion Intro

what is recursion?

  • a recursive function is a function that calls itself
  • a recursive algorithm appears in its own steps

why learn/use it?

  • to repeat something, like a loop
  • compared to iterative (loop) version, recursive algorithms can be simple and concise
  • more powerful than plain loops and nested loops
  • some problems are easier to understand through recursive algorithms, even if you end up converting it to an iterative algorithm
  • important in functional programming, math (have you seen proof by induction yet?)

why not use it?

  • expensive: function call overhead > loop overhead
    • some compilers can optimize recursive functions into loops
  • loops are equally powerful when combined with a stack

from section 7.1.1 of our textbook:

Newcomers who are unfamiliar with recursion often find it hard to accept that it is used primarily as a tool for simplifying the design and description of algorithms. A recursive algorithm does not always yield the most efficient computer program for solving the problem because recursion involves function calls, which are typically more expensive than other alternatives such as a while loop. However, the recursive approach usually provides an algorithm that is reasonably efficient. If necessary, the clear, recursive solution can later be modified to yield a faster implementation.

we’ll cover recursion in three phases:

  1. use recursive functions to perform iteration, imitate loops
  2. write more complex recursive functions involving branching/backtracking

  • depth-first search:

    • some implementations may involve mutable (changeable) state

Recursive Search Algorithms

practice: design and code recursive implementations of the linear search and binary search algorithms

function requirements:

  • takes the following parameters:
    • array of ints
    • start index (inclusive)
    • end index (exclusive)
    • x (the int to search for)
  • returns the index of x (if x is in the array) or -1 (if x isn’t in the array)

recursion design:

  • identify and describe base case(s)
    • condition
    • result
  • identify and describe recursive case(s)
    • condition
    • split into trivial problem (solve now) and smaller version of the main problem (solve recursively)

Stack ADT

what is it?

  • LIFO: last in, first out
  • simplest data structure to implement

IntStack ADT:

  • init(capacity: int) as with list, this is just our constructor and not part of our interface
  • push(element: int): boolean adds element to the stack, returning whether it succeeded
  • pop(): int removes and returns the top element from the stack; throws an EmptyStackException if the stack is empty
  • peek(): int as remove, but leaves the element on the stack
  • size(): int returns number of elements on the stack
  • clear() removes every element on the stack
  • isEmpty(): boolean returns size() == 0

Why not a list?

  • a proper list can do anything a stack can do and more
  • sometimes constraints are useful, and many algorithms can be implemented efficiently with a stack’s limited set of operations
  • we can make push and pop O(1) operations, and our code is far simpler if we don’t support other list operations

Array-Based Stack

  • IntArrayStack will look similar to our bad list class from a few weeks ago
  • all operations are simple because we never have to shift elements to make room; just add and remove at the end of the array (or the part that we’re using)
  • because the rest of the code is simple, this is a good time to show how to dynamically grow an array-based data structure

some problems we might want to solve with a stack:

  • implementing a depth-first search algorithm, such as the one from our maze assignment
  • implementing a calculator to evaluate postfix expressions
  • implementing any recursive algorithm without recursive functions: you only need a stack and one or more loops
  • the call stack used for function arguments and local variables
