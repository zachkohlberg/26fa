Task 1: Maze Class (5 points)

Write a Maze class (Maze.java). This class must have the variables, constructors, and methods described below. It should not include any other instance/static variables or instance methods.

  • instance variables (private)
    • data: char[][]
    • rows: int
    • cols: int
  • constructor
    • Maze(r: int, c: int)
      • initialize a new maze with r rows and c cols
      • initialize every character in the maze to MazeConstants.EMPTY
      • assume that r and c are positive
    • Maze(f: File) throws FileNotFoundException
      • initialize the maze with the information read from f
      • assume f is formatted exactly as described in the maze file format explained below
      • don’t catch the FNF exception, just let the caller deal with it (see the test code for an example)
  • methods
    • inBounds(row: int, col: int): boolean
      • returns true if and only if 0 <= row < rows and 0 <= col < cols
    • get(row: int, col: int): char
      • returns the character at the given row and column
      • throw an IndexOutOfBoundsException if the coordinates are out of bounds
    • set(row: int, col: int, symbol: char): void
      • sets the character at (x, y) to c
      • throw an IndexOutOfBoundsException if the coordinates are out of bounds
    • getRows(): int
    • getCols(): int
    • toString(): String
      • return a string representation of the maze
      • the rows must be in order starting with the first row (0) and ending with the last row (rows - 1)
      • each row must end with a newline character (\n), including the final row
      • the columns within each row must be in order starting with the first column (0) and ending with the last column (cols - 1)

Use the following test program to verify your Maze class works:

import java.io.File;
import java.io.FileNotFoundException;

public class MazeTest {
    public static void main(String[] args) {
        Maze maze1 = new Maze(4, 13);
        for (int i = 0; i < 26; i++) {
            maze1.set(i / 13, i % 13, (char) ('a' + i));
            maze1.set(2 + i / 13, i % 13, (char) ('A' + i));
        }
        test(maze1);
        // the for loop above should result in the following maze:
        //
        // abcdefghijklm
        // nopqrstuvwxyz
        // ABCDEFGHIJKLM
        // NOPQRSTUVWXYZ

        try {
            Maze maze2 = new Maze(new File("maze.txt"));
            test(maze2);
            // the maze should look exactly as shown in the file, minus the dimensions and comments
        } catch (FileNotFoundException e) {
            System.out.println(
                    "ERROR: You're missing maze.txt! Can't test whether the file constructor"
                            + " works.");
        }
    }

    public static void test(Maze m) {
        int rows = m.getRows();
        int cols = m.getCols();
        System.out.printf("%dx%d maze:\n%s\n\n", rows, cols, m);
        System.out.printf(
                "Corners:\n%s%s\n%s%s\n\n",
                m.get(0, 0), m.get(rows - 1, 0), m.get(0, cols - 1), m.get(rows - 1, cols - 1));
        // should say yes
        checkInBounds(m, 0, 0);
        checkInBounds(m, rows / 2, cols / 2);
        // should say no
        checkOutOfBounds(m, -1, 0);
        checkOutOfBounds(m, 0, -1);
        checkOutOfBounds(m, 0, cols);
        checkOutOfBounds(m, rows, 0);
        checkOutOfBounds(m, rows, cols);
    }

    public static void checkInBounds(Maze m, int row, int col) {
        if (m.inBounds(row, col)) {
            System.out.printf("CORRECT: r%dc%d is in bounds\n", row, col);
        } else {
            System.out.printf("  ERROR: r%dc%d is out of bounds\n", row, col);
        }
    }

    public static void checkOutOfBounds(Maze m, int row, int col) {
        if (m.inBounds(row, col)) {
            System.out.printf("  ERROR: r%dc%d is in bounds\n", row, col);
        } else {
            System.out.printf("CORRECT: r%dc%d is out of bounds\n", row, col);
        }
    }
}

Maze File Format

A properly-formatted maze file is structured as follows:

  • first line: the rows and cols separated by a space
  • maze: one line for each row, with each line containing a number of characters equal to the cols (in other words, the exact output of the toString method)
  • comments/extra: may have additional lines of text after the maze; these should be ignored when reading the file

Example maze file (save as maze.txt for the maze test program to find it):

5 19
# # ### #   #   ###
# # #   #   #   # #
### ### #   #   # #
# # #   #   #   # #
# # ### ### ### ###

This is extra text in the comments section. Your code shouldn't read this part,
or at least shouldn't use it when initializing a Maze object.

Also, nothing in the format says the maze file has to be an actual solvable
maze. This maze is just the word HELLO so you can tell that your maze read the
file correctly and that its toString method works correctly.

Coordinates

Our maze uses row/column coordinates instead of x/y coordinates. We could design the maze class to use either, but once we’ve made that choice we need to be consistent with the order of these coordinates and how we refer to them.

If we use x/y coordinates, then we expect the following:

  • x is the horizontal axis and y is the vertical axis
  • x is the first coordinate, and y is the second coordinate
  • width is the first dimension, and height is the second dimension
  • up is usually positive and down is usually negative

If we use row/column coordinates, then we expect the following:

  • row is the vertical axis (changing rows moves you up or down), and col is the horizontal axis
  • row is the first coordinate, and col is the second coordinate
  • rows is the first dimension, and cols is the second dimension
  • up is usually negative and down is usually positive

If you want the short version: row/col puts the vertical axis first, and x/y puts the horizontal axis first. To avoid mixing up the order and introducing some very annoying bugs, do not refer to your coordinates/dimensions as x, y, width, or height anywhere in your code! Use “rows” and “cols” instead of “width” and “height” to refer to the dimensions of a maze for the same reason.

If this sounds confusing, don’t worry! The difficulty here isn’t the code you’ll be writing, it’s thinking about the difference between x/y and row/col coordinates. I’m only explaining it so you know why the assignment works this way and can avoid some of the more common mistakes. You shouldn’t need to worry about the above explanation while coding as long as you follow the advice about not referring to variables as x, y, width, or height.

Task 3: Recursive Solve Method (5 points)

Add the MazeConstants.java file to your project folder before writing the solve method:

public class MazeConstants {
    public static final char EMPTY = ' ';
    public static final char PATH = '.';
    public static final char START = 'S';
    public static final char END = 'E';
    public static final char VISITED = 'v';
    public static final char WALL = '#';
}

We must obey the following rules when trying to solve the maze:

  • positions containing the space character ' ' are considered empty
  • positions containing any other character are considered occupied, and we cannot move through them
  • when we begin solving the maze, we will start at an empty position within the bounds of the maze
  • from our current position, we are allowed to move to the adjacent north, south, east, or west position as long as it is empty
    • for example, we could move from r3c7 to r4c7, which is one cell south, but not to r5c7 (two cells south) r4c8 (one cell diagonally southeast)
  • our goal is to find a path that leads from the start position to the end position

You will use the following recursive algorithm to solve the maze:

  • input
    • a maze to solve
    • a start row and start column
    • an end row and end column
  • first base case
    • condition: our start position is out of bounds or isn’t empty
      • you can use the maze’s get method to check whether a position is empty: m.get(12, 27) == MazeConstants.EMPTY will tell you whether r12c27 is empty
    • result: we’ve failed to solve the maze because we can’t move out of bounds or through an occupied cell
  • second base case
    • condition: our start position matches our end position
    • result: we’ve solved the maze!
  • recursive case
    • condition: base case conditions are false (in code, this should just be an else)
    • mark our starting position as MazeConstants.VISITED
      • you can use the maze’s set method to mark a position: m.set(5, 11, MazeConstants.VISITED); would mark r5c11 as visited
    • for each position we are allowed to move to, attempt to solve the maze starting at that position
      • these positions are (row - 1, col), (row + 1, col), (row, col - 1), and (row, col + 1)
    • if we succeed in solving the maze, then mark our starting position as MazeConstants.PATH

You must implement this algorithm as a recursive static method:

  • name: solveMaze
  • return type: boolean (true if solved and false if not)
  • parameters:
    • m: Maze is the maze to solve
    • startRow: int is the start row
    • startCol: int is the start column
    • endRow: int is the end row
    • endCol: int is the end column
